# 前端监控 SDK 的架构设计

> 我们设计一个前端监控 SDK，它需要收集多种类型的监控数据，包括性能数据、错误数据、用户行为数据等，并将这些数据发送到后端。同时，SDK 应该可扩展、可配置，并且尽量不影响主应用的性能。
> 架构设计考虑：
>
> 1.  模块划分：将不同的监控功能划分为独立的模块，例如错误监控、性能监控、用户行为监控等。
> 2.  插件化：允许用户按需加载监控模块，也便于扩展新的监控类型。
> 3.  数据上报：统一的数据上报机制，支持批量上报、节流、重试等。
> 4.  全局配置和每个模块的配置。
> 5.  尽量减少对业务代码的侵入，支持自动安装和手动安装。
>     我们采用类似 Vue 插件式的架构，同时参考 Sentery 等开源监控 SDK 的设计。
>
> 步骤：
>
> 1.  定义核心类（MonitorSDK），它负责管理所有插件（监控模块）和全局配置。
> 2.  每个监控模块是一个插件，需要实现一个固定的接口（例如 install 方法），以便在核心类中注册。
> 3.  数据上报使用一个统一的 Reporter 类，处理上报逻辑。
> 4.  支持在初始化时选择要启用的插件，并可以传递每个插件的配置。

## 分层架构设计

```txt
┌─────────────────────────────────────────┐
│               应用层                     │
├─────────────────────────────────────────┤
│                SDK核心                   │
├─────────────┬─────────────┬─────────────┤
│  数据采集层  │  数据处理层  │  数据上报层  │
└─────────────┴─────────────┴─────────────┘
```
